01 / Capabilities

What it answers

Plans and premiums

Subsidy estimates

Benchmark plans, expected contributions and premium tax credits from public data.

Drugs and providers

Formulary coverage and provider networks from each insurer's published files.

02 / Data integrity

Unknown stays unknown

  • When a file is missing, blocked or incomplete, the answer is unknown. OpenPlans never invents an answer or treats missing data as "not covered".
  • A state with no cited rating rule returns unsupported_rating_method rather than a guessed premium.
  • Each imported file becomes a snapshot with its URL, checksum and parser version. OpenPlans holds back partial imports and never serves them.
  • OpenPlans labels fallbacks. If it finds a county through a secondary source, the answer names that source.

03 / Integration

Two APIs, same answers

OpenPlans has a native JSON API and a compatibility API. Existing quoting integrations can use the compatibility API to switch with fewer changes. Both use only public data.

06 / Availability

Coverage today

Premiums

All federal-platform states for 2026 and 2027. The 22 state-exchange states for 2026, from CMS state-based exchange files; their 2027 files are not published yet. New York and Vermont from their filed rates. Stand-alone dental. Silver cost-sharing reduction variants.

Drugs and providers

Texas, Florida and North Carolina, for every insurer whose published files could be read. Other states are next.

Not yet

State-exchange subsidy rules, and drugs and providers outside Texas, Florida and North Carolina.

08 / Publishers

For data publishers

If you saw this address in your server logs, it came from the OpenPlans fetcher. It identifies itself as:

openplans/0.1 (public health-plan source discovery; +https://plans.openhra.com/)
  • It downloads only files you publish for the public, such as machine-readable QHP indexes, formularies and provider directories.
  • It never pretends to be a browser and never works around access controls or bot checks. A 401 or 403 is recorded and not retried.
  • It retries only short-lived errors (timeouts, 429, 5xx), with backoff, and honours Retry-After.
  • Each file is stored once by checksum and reused, so the same file is not downloaded again without a reason.
  • OpenPlans is self-hosted, so requests with this identity may come from different organisations running their own copy.
